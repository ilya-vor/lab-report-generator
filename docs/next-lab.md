# Как сделать следующую лабораторную

## 1. Скопировать репозиторий

Скопируйте папку `lab-report-generator` в новый каталог, например `lab2`.
Это сохранит рабочий каркас (шаблон, скрипты, документацию).

## 2. Подготовить схему процесса

Откройте `generate_scheme.py` и отредактируйте данные:

- `LANES` - список ролей / подразделений (дорожки).
- `NODES` - узлы процесса, формат
  `("Id", "type", "Название", lane, col, offset)`.
  Типы: `task`, `xor`, `start`, `end`, `timer`.
- `FLOWS` - связи, формат
  `("Id", "Source", "Target", "метка", True/False)`.
- `PROBLEM_STYLE` - какие узлы подсветить и каким цветом.
- Геометрия (шаг колонок, высота дорожек, размеры блоков) - в блоке констант
  в начале файла.

Запуск:

```
python generate_scheme.py
```

## 3. Настроить отчёт

В `build_report_docx.py` в блоке `НАСТРОЙКИ` поменяйте:

- `FULL_TITLE`, `SHORT_TITLE` - тема;
- `DEPT`, `DISCIPLINE`, `TEACHER`, `GROUP`;
- `OLD_*` - значения, которые стоят в шаблоне (по ним идёт замена);
- `OUT` - имя итогового документа;
- `IMG` - имя картинки схемы.

Наполнение отчёта (разделы, таблицы) правится в `build_content(doc)`.

## 4. Собрать

```
python build_report_docx.py
powershell -NoProfile -ExecutionPolicy Bypass -File update_fields.ps1 -Path "ваш_отчет.docx"
```

## 5. Опционально: правка схемы в Camunda

- Откройте `.bpmn` в Camunda Modeler, поправьте, сохраните.
- `File -> Export As -> PNG`, сохраните поверх файла из `IMG`.
- Пересоберите отчёт (`python build_report_docx.py`).

## Чек-лист

- [ ] Схема: есть начальное и конечное события, все узлы разложены по дорожкам,
      исключения оформлены XOR-шлюзами, покрытие сценариев >= 80 %.
- [ ] Есть минимум 3 проблемные точки с обоснованием.
- [ ] Титул на одной странице, группа не переносится на вторую строку.
- [ ] Оглавление обновлено, номера страниц верны.
- [ ] В тексте нет длинных тире (заменены смысловыми связками).
